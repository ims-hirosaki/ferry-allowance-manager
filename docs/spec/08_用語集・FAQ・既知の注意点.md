# 08 用語集・FAQ・既知の注意点

## 1. 用語集

| 用語 | 読み | 意味 |
|---|---|---|
| フェリー手当 | – | 1回のフェリー乗船ごとに社員へ支払う手当（円）。航路ごとの固定額 |

| フェリー会社マスタ | – | フェリー会社名の一覧（`ferry_companies`）。航路に紐づける |
| 乗車月日 | – | 乗船した日（DATE、`use_date`） |
| 車番 | しゃばん | 車両管理ツールの**一連指定番号**（serial_number）。`vehicle_code` |
| 乗車名 | じょうしゃめい | 乗船した社員。社員コードで保存、画面は氏名表示 |
| 乗車名マスタ | – | 「車番→通常乗る社員」の対応表（`ferry_vehicles`）。入力時に乗車名を自動表示するための補助 |
| 手動選択（例外選択） | – | 代役などイレギュラー時に、乗車名マスタを無視して社員を直接選ぶ操作 |
| 運輸支局 | うんゆしきょく | 車両が属する運輸支局名。車両管理から取得し、一覧で表示 |
| スナップショット | – | 登録時点の値を実績にコピー保存すること。マスタ変更が過去実績に影響しないようにする |
| ライブ解決 | – | 表示時に最新のマスタ（社員情報など）を引くこと。取れなければ保存値を使う |
| 月次サマリ | – | 社員別の月間手当合計と件数の集計画面。給与ソフト入力用 |
| 社員コード | – | 社員情報管理の社員の識別コード（`employee_code`） |
| 無効化 | – | 物理削除せず「使わない」状態にする操作（`is_active=0`） |
| 重複警告 | – | 同一社員・日付・航路の実績が既にあるときの警告（登録は行われる） |
| nonce | ノンス | WordPress のCSRF対策用の一時トークン |
| capability | – | WordPress の権限名 |
| `faData` | – | PHPからJSへ渡すデータオブジェクト |
| `FA_` | – | 本プラグインのクラス接頭辞（Ferry Allowance） |
| 一連指定番号 | いちれんしていばんごう | vehicle-manager 上の車両識別番号。本プラグインでは「車番」 |

## 2. FAQ

### 2-1. 利用者向け

**Q1. 1日に同じ航路を2回乗った。どう入力する？**
A. 同じ日付・同じ航路で**2行**入力します。同じ社員・同じ日付・同じ航路になるので重複警告が出ますが、登録は行われます（意図した2回なら問題ありません）。

**Q2. 入力した中の1行だけミスがあった。他の行は登録される？**
A. いいえ。**1行でもエラーがあるとその回は全件登録されません**。エラーを直して再度「登録」を押します。

**Q3. 航路の手当額を変えたい。過去の分も変わる？**
A. 航路マスタで金額を変えると、以後の新規登録から新しい額です。登録済みの実績は変わりません。ただし、登録済みの実績を**更新（編集して「更新」）すると新額になる**ので注意してください。

**Q4. 乗車名が間違って自動表示される。**
A. 乗車名マスタ（車番⇄社員）が古い可能性があります。その場だけなら「手動選択」で正しい社員に変更、恒久なら管理者に乗車名マスタの更新を依頼します。

**Q5. 月次サマリの氏名が、登録した時と違う。**
A. 氏名は表示時に社員情報の最新の氏名が使われます（社員情報側で変更があった場合）。金額・件数は実績の保存値です。

**Q6. サマリをExcelに取り込みたい。**
A. 月次サマリの「CSV出力」を使います（UTF-8 BOM付き）。氏名／フェリー手当（月）／件数の3列です。

**Q7. 実績を消してしまった。元に戻せる？**
A. 戻せません（物理削除）。再度入力してください。

**Q8. 古い実績の航路が空欄になる／編集で航路が選べない。**
A. 航路が無効化または削除されている可能性があります。実績一覧の表示は保存した航路名で出ますが、編集して更新するには有効な航路を選び直す必要があります。

**Q9. 備考欄はどこ？**
A. 画面にはありません（データ項目としては存在しますが、入力・編集できません）。

### 2-2. エンジニア向け

**Q10. 氏名をマスタ変更に追従させたくない場合は？**
A. 現状、一覧・サマリは `FA_Employee_Bridge::resolve_name` で最新氏名を優先します。保存氏名優先にするには `get_records` と `get_month_summary` の解決順を変更します。

**Q11. 手当額の更新漏れを防ぎたい（更新時に旧額を維持したい）。**
A. `FA_Record::update` を、航路・日付・社員・車番が変わらない場合は `allowance` を再取得しないよう変更します。現状は常に再取得します。

**Q12. 同一社員・同日・同航路の重複を禁止したい。**
A. 要件として警告のみ許可。禁止するなら `save_bulk`/`update` の重複判定箇所をエラー化、必要なら UNIQUE 制約を追加（既存重複データの整理が先）。

**Q13. 他システム（給与ソフト）連携を追加するには？**
A. 現状は月次サマリのCSV（JS生成）のみ。`FA_Summary::get_month_summary` が集計の唯一の入口なので、サーバー側CSV/APIを作る場合はここを再利用します。コメントに「全ツールのCSV統合時は撤去」とあり、統合方針は別途検討されています。

**Q14. 画面を追加するには？**
A. `FA_Admin_Menu` の `$pages`（アセット読込対象）とメニュー登録、`admin/views/` にビュー、`admin.js` の画面分岐（`switch (FA.page)`）、AJAX は各クラスに `ajax_*` と `register_ajax_hooks` を追加します。

## 3. 既知の注意点・制約（ソースから読み取れる事実）

> 「不具合」と断定せず、現状の挙動を事実として記載します。改修や運用判断の材料にしてください。

| # | 内容 | 影響 | 根拠 |
|---|---|---|---|
| 1 | **アンインストールで `ferry_companies` が削除されない**（`drop_tables()` の対象に含まれない） | プラグイン削除後もフェリー会社テーブルが DB に残る | `class-db-install.php` `drop_tables()` |
| 2 | **実績の更新で `note`（備考）が空に上書きされる**。画面（入力・編集）に備考欄がなく、更新リクエストに `note` が含まれない | 備考をDBへ直接入れても、画面から実績を更新すると消える | `admin.js` `update()`、`FA_Record::ajax_update` |
| 3 | **実績を更新すると手当額・航路名・会社名が現在のマスタ値に再取得される** | 手当改定後に古い実績を編集すると新額になる | `FA_Record::update` |
| 4 | **サーバー側は乗車名マスタとの一致を検証しない** | 任意の実在社員コードで登録可能（手動選択は仕様） | `FA_Record::save_bulk` |
| 5 | **社員の「在籍」は実績登録時に検証されない**（存在のみ）。乗車名マスタ保存時は在籍を検証 | 退職者でも社員APIが返せば登録可能な可能性 | `FA_Employee_Bridge::get_by_code` と `exists_active` の使い分け |
| 6 | **入力エラーの行番号が、クライアント（表の位置）とサーバー（空行を除いた順）で異なり得る** | 空行を挟んで入力するとサーバー側エラーの「○行目」がずれる | `admin.js` 保存ボタン処理、`FA_Record::save_bulk` |
| 7 | **一括登録はトランザクション未使用** | 検証は全件先に行うが、INSERT途中の障害で一部のみ登録される可能性がある | `FA_Record::save_bulk` |
| 8 | **航路マスタのフェリー会社セレクトは「有効な会社のみ」・ページ読込時に生成** | 無効な会社が紐づいた航路を編集すると、会社欄が「未設定」表示になり、そのまま更新すると会社紐づけが外れる | `routes.php`、`FA_Company::get_list()`、`FA_Route::save` |
| 9 | **会社・航路は物理削除で、参照整合性チェックなし** | 会社を消すと、航路の `company_id` は残るが会社名は解決されず空欄になる | `FA_Company::delete`、`FA_Route::get_list` |
| 10 | **航路を全件削除すると、有効化/バージョン更新時に初期24件が再投入される** | 意図せず初期航路が復活する | `FA_DB_Install::seed_routes` |
| 11 | **無効な航路は、実績の編集画面で航路欄に復元されない（航路番号のみ）** | 無効航路の実績は、更新時に有効航路を選び直す必要がある | `admin.js` `openEdit`、`FA_Route::get_by_no` |
| 12 | **実績一覧の期間条件が空（年月も日付範囲もなし）だと全期間を取得** | 画面からは常に年月が渡るので通常は発生しない（API直叩き時のみ） | `FA_Record::period_where` |
| 13 | **乗車名マスタの一覧検索は車番・社員コードのみ（氏名不可）**。並びは `CAST(vehicle_code AS UNSIGNED)` 優先のため、英字を含む車番は数値部分（先頭の数字）が基準になる | 検索・並び順の想定違い | `FA_Boarding_Name::get_list` |
| 14 | **乗車名マスタの編集時、画面は車番を固定（disabled）だが、サーバーは車番変更も受け付ける** | 通常画面操作では起きない | `admin.js`、`FA_Boarding_Name::save` |
| 15 | **閲覧のみの権限でも編集系ボタン・登録ボタンが表示される** | 押すと「権限がありません。」になる | 各ビュー／`verify()` |
| 16 | **`*_toggle` / `*_delete` のAJAXは、対象が無くても成功扱い（`success:true`）で内側に `success:false` を持つ** | フロントは `res.data.message` を表示するので気づきにくい | 各 `ajax_toggle`/`ajax_delete` |
| 17 | **`uninstall.php` のバージョンフォールバックが `1.2.0`**（本体は `1.3.0`） | 動作影響なし（表示・判定に使われない） | `uninstall.php` |
| 18 | **サマリCSVの合計行なし／氏名のみで社員コードを含まない** | 給与ソフトへ社員コードで突合したい場合は別途対応が必要 | `admin.js` CSV処理 |
| 19 | **月次サマリは社員コード（文字列）順** | 数値として並ぶとは限らない（例: "100" が "20" より前） | `FA_Summary::get_month_summary` |
| 20 | **`ferry_records.route_id` は論理参照。実績の重複判定は `route_id` で行う** | 航路を削除→再作成（番号同じ・IDが変わる）すると、同日同社員同航路でも重複扱いにならない | `save_bulk`/`update` の重複SQL |

## 4. 仕様の確認が必要な点（【推測・要確認】）

1. `access_custom_plugins` / `edit_custom_plugins` を付与するロールの割り当て（本リポジトリには定義なし）。
2. employee-manager の `emp_get_employee_by_code` が退職者を返すか、`is_active` を持つか。
3. vehicle-manager の `vm_get_transport_bureau(_map)` の導入状況（旧版は運輸支局が空）。
4. 給与ソフト取込の実フォーマット（現状のCSVは氏名・金額・件数のみ）。
5. 本番運用中のフェリー会社・航路・手当額の現在値（コードの初期値は24航路のみで会社の紐づけなし）。
