# 04 業務ルール・計算仕様

この章は「金額がどう決まるか」「何がいつ確定し、何が後から変わるか」を、利用者・エンジニア双方に向けて説明します。

## 1. フェリー手当の決まり方

**手当額は航路ごとに決まった固定額です。**（距離・車種・人数などによる計算はありません。）

```
1回の乗船の手当 ＝ その航路の航路マスタの「フェリー手当（円）」
```

- 往復は「行き」「帰り」で**2行（2回分）**入力し、それぞれ手当が付きます。
- 手当は0円も可能（航路マスタの手当は0以上）。
- 金額は整数（円）。小数や税の扱いはありません。

## 2. スナップショット（登録時点の値の保存）

実績を登録（または更新）するとき、次の値をその時点のマスタ等から**実績にコピーして保存**します。

| 保存される項目 | コピー元 | 後でコピー元が変わると？ |
|---|---|---|
| 航路番号・航路名 | 航路マスタ | 実績は変わらない |
| 手当額（allowance） | 航路マスタ | 実績は変わらない（**更新すると新額に再取得**） |
| フェリー会社（ID・名称） | 航路マスタ→会社マスタ | 実績は変わらない |
| 社員コード・氏名 | 乗車名（社員情報） | 社員コードは固定。**氏名は表示時に最新を優先**（下記） |
| 車番 | 入力値 | 固定 |
| 運輸支局 | vehicle-manager（車番から） | 表示時は最新を優先、取れなければ保存値 |

### 表示時の優先ルール（ライブ解決）

| 項目 | 表示時に使う値 |
|---|---|
| 乗車名（氏名） | ①社員情報の現在の氏名 → ②無ければ実績に保存した氏名 → ③（サマリのみ）さらに無ければ社員コード |
| 運輸支局 | ①vehicle-manager の現在の運輸支局（車番で引く）→ ②無ければ実績に保存した値 |
| 航路名・フェリー会社・手当額 | 常に実績に保存した値（マスタは参照しない） |

**意味**: 手当額・航路名などは「当時の金額」で固定され、過去の給与計算がぶれません。一方、氏名は改姓などの変更が一覧・サマリにも反映されます。

### 実績を「更新」したときの再取得

実績更新（`FA_Record::update`）は、新規登録と同じ検証を行い、**航路・社員・運輸支局のスナップショットをすべて取り直します**。

- 航路マスタの手当額を変えたあとで、古い実績を（日付だけでも）更新すると、**新しい手当額で上書き**されます。
- 無効化・削除された航路の実績を更新するには、有効な航路を選び直す必要があります（`get_by_no` は有効な航路のみ返すため）。
- `updated_at` が更新されます。

## 3. 登録時の検証ルール（一括登録）

### 3-1. 全か無かの原則

複数行をまとめて登録するとき:

1. すべての行を検証する（途中で1行エラーが出ても残りの行も検証し、エラーを全部集める）。
2. **1行でもハードエラーがあれば、何も登録しない**（全体を差し戻し、エラー一覧を返す）。
3. ハードエラーがなければ**全行を登録**する。
4. 重複は**警告のみ**で、登録は行う。

### 3-2. ハードエラー条件（サーバー側）

| 項目 | エラー条件 | メッセージ |
|---|---|---|
| 乗車月日 | 空／`YYYY-MM-DD` として存在しない日付 | ○行目：乗車月日が正しくありません（YYYY-MM-DD）。 |
| 航路番号 | 0以下 | ○行目：航路番号を入力してください。 |
| 航路 | 航路マスタに無い／**無効** | ○行目：航路番号 N は航路マスタに見つかりません。 |
| 車番 | 空 | ○行目：車番を入力してください。 |
| 車番 | vehicle-manager に実在しない | ○行目：車番 X は車両管理ツールに登録されていません。車両管理画面から登録してください。 |
| 乗車名 | 社員コードが空 | ○行目：乗車名を入力してください。 |
| 乗車名 | 社員情報に存在しない | ○行目：乗車名（社員コード X）が社員情報に見つかりません。 |
| 全体 | 行が0件 | 登録するデータがありません。 |

エラー時の全体メッセージ: 「入力内容にエラーがあります。修正してください。」＋ `errors[]`。

> サーバー側は、乗車名が「車番の乗車名マスタと一致しているか」を**検証しません**。実在する社員コードであれば（手動選択の結果でも）保存されます。乗車名マスタは入力補助（自動表示）の位置づけです。

### 3-3. 重複判定（警告のみ）

- 条件: **同じ社員コード＋同じ乗車月日＋同じ航路（航路ID）** の実績が、既に登録済みで存在する。
- 動作: 警告を返すが、**登録は行う**。メッセージ例: 「氏名／2026-10-05／神戸 ⇔ 新門司：同じ実績が既にあります（重複登録しました）。」
- 判定は**登録済みデータとの比較**。同じ送信内の行同士（同時に送った2行が同一）は、先に処理した行が登録された後に次の行を判定するため、2行目に警告が出ます（登録順に1行ずつINSERTするため）。
- 更新時: 自分自身を除いて同条件を判定し、あれば「同じ社員・日付・航路の実績が他にもあります（更新は行いました）。」を返す。

## 4. 月次サマリの集計ルール

`FA_Summary::get_month_summary(year, month)`

1. 期間: 指定月の1日〜末日（`use_date BETWEEN`）。
2. **社員コードごと**に集計（`GROUP BY employee_code`）:
   - 手当合計 = `SUM(allowance)`（実績に保存された手当額の合計。マスタの現在額ではない）
   - 件数 = `COUNT(*)`
3. 実績がある社員のみ（0件の社員は出ない）。並びは社員コード昇順（文字列順）。
4. 氏名: 社員情報の最新氏名 → 無ければ実績の保存氏名 → 無ければ社員コード。
5. 合計金額・合計件数を全社員分足し上げて返す。
6. 年が0以下、月が1〜12以外なら、空の結果を返す。

| 返却項目 | 内容 |
|---|---|
| `items[]` | `employee_code`, `employee_name`, `total`, `count` |
| `grand_total` | 全員の手当合計 |
| `grand_count` | 全員の件数合計 |
| `period` | `YYYY-MM`（不正な年月は空文字） |

### サマリの集計単位（社員のみ）

サマリは**社員単位のみ**です。車番別・航路別・会社別の集計機能はありません（一覧で並べ替え・絞り込みして目視する想定）。

## 5. CSV出力仕様（月次サマリ）

| 項目 | 内容 |
|---|---|
| 生成場所 | ブラウザ（JS）。サーバーはAPI（`fa_summary_get`）が返すデータのみ提供 |
| ファイル名 | `ferry-allowance-YYYY-MM.csv`（月は0埋め2桁） |
| 文字コード | UTF-8、先頭に BOM（`U+FEFF`） |
| 改行 | CRLF（最終行にも付与） |
| 見出し行 | `氏名`, `フェリー手当（月）`, `件数` |
| データ行 | 社員ごとに「氏名, 合計金額, 件数」。合計行は**出力しない** |
| 引用 | すべてのセルを `"` で囲み、内部の `"` は `""` にエスケープ |
| 数式インジェクション対策 | 空白を除く先頭が `=` `+` `-` `@`、または先頭が タブ/CR/LF のセルは、先頭に `'` を付ける |
| 数値 | カンマなしの整数（3桁区切りなし） |
| 注記 | コメントで「暫定CSV出力：全ツールのCSV統合時はこのブロックと専用ボタンを撤去する」とある（将来、他ツールとのCSV統合で置換予定） |

## 6. マスタの状態遷移と影響範囲

| 操作 | 新規入力への影響 | 既存実績への影響 |
|---|---|---|
| 航路を**無効化** | 入力候補から消える。サーバー側でも「見つかりません」エラー | なし（保存値のまま）。**更新時**は航路選び直しが必要 |
| 航路を**削除**（物理） | 同上 | なし（保存値のまま）。実績の `route_id` は残るが参照先は無い |
| 航路の**手当額変更** | 以後の登録・更新は新額 | 登録済みは変わらない。**更新すると新額** |
| 航路の**フェリー会社変更** | 以後の登録・更新に反映 | 登録済みは変わらない |
| フェリー会社を**無効化** | 航路マスタの会社選択肢に出なくなる（既存の航路の会社紐づけは残る） | なし |
| フェリー会社を**削除** | 航路の会社は「未設定」表示になる（航路の `company_id` は残るが解決不可） | なし（実績に会社名を保存済み） |
| 乗車名マスタを変更／無効化／削除 | 入力時の乗車名自動表示が変わる | なし |
| 社員が在籍でなくなる／車両管理から車番が消える | 乗車名マスタの該当行は入力の自動表示に使われなくなる | 実績は残る。氏名は取得できれば最新、無理なら保存値 |

## 7. 入力補助ルール（自動反映の仕組み）

### 7-1. 航路の自動反映
`faData.routes`（**有効な航路のみ**）から `route_no → {name, allowance, company}` を作成。航路名検索の文字列から**先頭の数字列**を航路番号として扱う（`"12 新潟 ⇔ 敦賀"`→12、`"12"`→12）。

> 注意: 航路名に数字が含まれていても、番号が先頭に付く形式（候補の選択）を前提とします。航路名だけを手入力すると、先頭の数字列の有無で解釈が変わります。

### 7-2. 乗車名の自動表示（車番→社員）
`faData.vehicleEmployees` は `FA_Boarding_Name::get_map_for_js()` で作成され、次の**3条件をすべて満たす行だけ**が入ります。

1. 乗車名マスタで**有効**（`is_active=1`）
2. その車番が vehicle-manager に**現在も登録されている**
3. その社員が**在籍社員一覧**に含まれている

### 7-3. 日付の入力
入力画面の日付は `type=date` ですが、`2026/10/05`、全角数字、`2026.10.5` などの貼り付けも `normalizeDate` で `YYYY-MM-DD` に整えます。実在しない日付（例: 2月30日）は不正（赤表示）。

## 8. 期間・年月の扱い

- 年月選択肢: 当年+1〜当年-3（5年分）、月は1〜12。初期値は WordPress のタイムゾーン設定（`current_time`）の現在年月。
- 月の範囲: 1日〜`Y-m-t`（月末）。
- 日付範囲（実績一覧）: `date_from`/`date_to` のどちらかでも妥当な日付なら**年月指定より優先**（片側のみ指定も可: 以降／以前）。
