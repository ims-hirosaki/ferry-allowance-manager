# 07 外部連携・権限・運用

## 1. 依存プラグイン

| 依存先 | 必須 | 判定に使う関数 | 未導入時の挙動 |
|---|---|---|---|
| employee-manager（社員情報管理システム） | 必須 | `emp_get_active_employees` | 有効化不可／運用中に無効化されると管理画面に赤い通知を出して機能停止 |
| vehicle-manager（車両管理） | 必須 | `vm_get_vehicle_numbers` | 同上 |

有効化時のエラー文言: 「**フェリー手当管理** を有効化するには、先に **employee-manager（社員情報管理システム）** プラグインを有効化してください。」（vehicle-manager も同様の文言）。本プラグインは自動で無効化されます。
運用中の通知: 「フェリー手当管理: employee-manager（社員情報管理システム） と vehicle-manager（車両管理） の両プラグインが必要です。先に有効化してください。」

## 2. 連携する外部関数（契約）

本プラグインが期待する、他プラグイン側の公開関数です。これらの引数・戻り値が変わると本プラグインが影響を受けます。

### employee-manager

| 関数 | 期待する動作 |
|---|---|
| `emp_get_active_employees($args)` | 在籍社員オブジェクト配列（`employee_code`, `name`, `crew_code` など） |
| `emp_get_employee_by_code($code)` | 社員コードで1件（オブジェクト or null）。`name`、`is_active`（あれば）を使用 |
| `emp_get_employee_by_id($id)` | 社員IDで1件（ブリッジに定義あり。現状は主要フローで未使用） |

### vehicle-manager

| 関数 | 期待する動作 |
|---|---|
| `vm_get_vehicle_numbers()` | 登録車番（一連指定番号）の配列 |
| `vm_vehicle_exists($code)` | 車番が登録されているか（bool） |
| `vm_get_transport_bureau_map()` | `車番 => 運輸支局` の配列（任意。無い版でも動作） |
| `vm_get_transport_bureau($code)` | 指定車番の運輸支局（任意。無ければ空文字） |

運輸支局関連の2関数は、**未対応の旧 vehicle-manager でも本プラグインは動作**し、運輸支局列が空になります。

### 画面遷移リンク（未登録時の誘導）

| 用途 | URL |
|---|---|
| 車両の新規登録 | `admin.php?page=vm-vehicle-form` |
| 社員の新規登録 | `admin.php?page=employee-manager-new` |

## 3. 権限（capability）モデル

| capability | 役割 | 使用箇所 |
|---|---|---|
| `access_custom_plugins` | 社内カスタムプラグインの**閲覧**権限 | 全メニュー・全画面の表示、一覧取得系 AJAX（実績・航路・会社）、月次サマリ |
| `edit_custom_plugins` | 社内カスタムプラグインの**編集**権限 | 実績の登録・更新・削除、航路・会社の保存・切替・削除 |
| `manage_options` | WordPress **管理者** | 乗車名マスタのタブ表示とその全AJAX |

### 画面ごとの権限一覧

| 機能 | 閲覧 | 編集 |
|---|---|---|
| フェリー手当入力（画面） | `access_custom_plugins` | 登録は `edit_custom_plugins` |
| 実績一覧・編集 | `access_custom_plugins` | 更新・削除は `edit_custom_plugins` |
| 月次サマリ・CSV | `access_custom_plugins` | （編集なし） |
| 航路マスタ | `access_custom_plugins` | `edit_custom_plugins` |
| フェリー会社マスタ | `access_custom_plugins` | `edit_custom_plugins` |
| 乗車名マスタ | `manage_options` | `manage_options` |

### 権限の挙動で注意すべき点

- 閲覧権限だけのユーザーは**入力画面を開けるが、「登録」を押すと「権限がありません。」**になります（画面側では編集ボタンを隠さない）。
- 乗車名マスタのタブは `manage_options` を持たないユーザーには表示されません。URLで直接指定しても `current_tab()` が先頭の許可タブ（航路マスタ）へ戻します。
- ただし、乗車名マスタの**「手動選択」や自動表示用のデータ**（`vehicleEmployees`, `employees`）は、`access_custom_plugins` があるユーザーの全画面に渡ります（読み取り用データ）。
- `access_custom_plugins` / `edit_custom_plugins` は**本プラグイン内で定義・付与していません**。社内の他の仕組み（git履歴に「ロール管理設定」のコミットがありますが、該当コードは本リポジトリ外）で付与されると考えられます。【推測・要確認】どのロールに付与するかは WordPress 側のロール管理で確認してください。

## 4. インストール・有効化・更新・削除

### 4-1. インストール手順（運用想定）

1. employee-manager と vehicle-manager を有効化（先に）。
2. 本プラグインのディレクトリ `ferry-allowance-manager` を `wp-content/plugins/` に配置（FTPデプロイ、下記）。
3. 管理画面でプラグイン「フェリー手当管理」を有効化 → テーブル4つ作成、航路24件投入。
4. フェリー会社マスタ登録 → 航路に会社を紐づけ → 乗車名マスタ登録 → 運用開始。

### 4-2. 更新（バージョンアップ）

コード更新後、最初のページ読み込み（`plugins_loaded`）で `fa_db_version` と `FA_VERSION` を比較。違えば `activate()` が走りスキーマが更新されます。**バージョンを上げ忘れるとスキーマ更新が走りません**。

### 4-3. 無効化・削除

| 操作 | 結果 |
|---|---|
| 無効化 | データは全部残る。メニューが消える |
| 削除（アンインストール） | `ferry_records`, `ferry_vehicles`, `ferry_routes` を DROP、`fa_db_version` オプション削除。**`ferry_companies` は残る**（実装上の漏れの可能性。`08` 参照） |

**実績データが消えるため、削除前にバックアップが必要です。**

## 5. デプロイ（GitHub Actions）

いずれも「FTP Deploy」（`SamKirkland/FTP-Deploy-Action`）で、このリポジトリの内容をサーバーのプラグインディレクトリへ転送します。接続先・認証情報は GitHub の Secrets（リポジトリ設定）に保存され、コードには含まれません。

| ワークフロー | 起動条件（push先ブランチ） | デプロイ先 | 備考 |
|---|---|---|---|
| `deploy.yml` | `main` | 本番サイト（社内システム）のプラグインディレクトリ | `dangerous-clean-slate: false`（サーバー側の余分なファイルを消さない） |
| `staging-deploy.yml` | `staging` | ステージング（テスト）サイト | `local-dir: ./` |
| `personal-deploy.yml` | `feature/shiroto*` | 個人テスト環境 | 開発者個人の確認用 |

開発フロー（git履歴から）: 機能ブランチ（例 `feature/records-transport-bureau-sort`）→ プルリクエスト → `main` マージ → 自動で本番デプロイ。履歴上は `staging` ブランチ経由でステージング確認後に本番へ反映した時期もあります。
注意: `main` へのマージ＝**即本番反映**です。

## 6. 運用で確認するポイント（チェックリスト）

| タイミング | 確認 |
|---|---|
| 月初（前月分の集計） | 月次サマリの対象年月を前月にして表示→CSV出力。実績一覧で重複・誤入力を確認 |
| 航路の手当額改定時 | 航路マスタで金額変更 → 以後の新規登録に反映。過去実績は変わらない。**改定前の実績を編集（更新）しない**（更新すると新額に変わる） |
| 新しい車両・社員の追加 | 先に車両管理・社員情報へ登録 → 乗車名マスタに紐づけ |
| 担当ドライバーの変更 | 乗車名マスタの該当車番を編集（過去実績は不変） |
| 航路・会社の廃止 | 削除ではなく無効化（過去分の表示・金額は保存値で保たれる） |
| プラグイン削除前 | 実績データのバックアップ（DB） |

## 7. 保守・トラブルシュート（エンジニア向け）

| 症状 | 想定原因 | 確認先 |
|---|---|---|
| メニューが出ない | `access_custom_plugins` 無し／依存プラグイン未有効 | ユーザーのロール、依存プラグイン |
| 「権限がありません。」 | `edit_custom_plugins` 無し（乗車名マスタは `manage_options`） | ロール設定 |
| 車番が全部「登録されていません」 | `vm_vehicle_exists` が未定義（ブリッジは false を返す）／vehicle-manager 無効 | vehicle-manager のバージョン・有効化 |
| 運輸支局が空 | vehicle-manager が運輸支局API未対応、または車番に未設定 | `vm_get_transport_bureau(_map)` |
| 乗車名が自動表示されない | 乗車名マスタ未登録／無効／車番が車両管理に無い／社員が在籍でない | 乗車名マスタ、employee-manager |
| 画面が動かない | `admin.js` の読み込みエラー、`faData` 未定義 | ブラウザのコンソール、キャッシュ（`FA_VERSION` を上げると更新される） |
| 新しい列が反映されない | `FA_VERSION` を上げていない | `fa_db_version` オプション |
| 航路が24件に戻った | 航路を全削除した後に有効化/バージョン更新が走った（シード再投入） | `seed_routes()` の仕様 |
