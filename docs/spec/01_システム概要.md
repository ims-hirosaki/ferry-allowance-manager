# 01 システム概要

## 1. 目的と背景

フェリーを利用する長距離輸送では、航路ごとに社員へ**フェリー手当**を支払います。本プラグインは次を一つの画面群で完結させます。

1. フェリー利用実績を**まとめて登録**する（複数行を1枚のシートで入力）
2. 航路を選ぶだけで**フェリー会社・航路名・手当額が自動入力**される
3. 登録済み実績を**月ごとに確認・修正・削除**する
4. **社員ごとの月間手当合計と件数**を集計し、給与ソフトへ入力する数字として表示・CSV出力する
5. **航路・フェリー会社・乗車名（車番と社員の対応）**のマスタを管理する

## 2. 想定する利用者（ロール）

| 利用者 | 主な作業 | 必要な権限（capability） |
|---|---|---|
| 入力担当 | 実績の登録・修正・削除 | `access_custom_plugins`（画面表示）＋ `edit_custom_plugins`（保存・更新・削除） |
| 給与担当・確認者 | 実績一覧の確認、月次サマリ・CSV | `access_custom_plugins` |
| マスタ管理者 | 航路・フェリー会社マスタの編集 | `access_custom_plugins`＋`edit_custom_plugins` |
| サイト管理者 | 乗車名マスタの管理 | `manage_options`（WordPress 管理者権限） |

> 権限名は WordPress の capability です。`access_custom_plugins` / `edit_custom_plugins` は本プラグインでは定義しておらず、社内の他の仕組み（ロール管理）で付与される前提です。【推測・要確認】詳細は `07_外部連携・権限・運用.md`。

## 3. 画面一覧とメニュー構成

WordPress 管理画面の左メニューに「**フェリー手当**」（アイコン: dashicons-sos＝浮き輪、表示位置 32、「有給管理(31)の直下」）が追加されます。

```
フェリー手当（トップ ＝ フェリー手当入力）
├── フェリー手当入力      page=ferry-allowance
├── 月次サマリ            page=ferry-allowance-summary
├── 実績一覧・編集        page=ferry-allowance-records
└── マスタ管理            page=ferry-allowance-master（タブ切替）
      ├── 航路マスタ           tab=routes（既定）
      ├── フェリー会社マスタ   tab=companies
      └── 乗車名マスタ         tab=boarding-names（管理者のみ）
```

- 旧URL（`ferry-allowance-routes` / `ferry-allowance-companies` / `ferry-allowance-boarding-names`）は、新しいタブ付きURLへ自動転送されます（ブックマーク対策）。
- 不正な `tab` 値、または権限のないタブを指定すると、「航路マスタ」タブが表示されます。

【ソース】`admin/class-admin-menu.php`

## 4. システム構成

```
┌────────────────────────── WordPress ──────────────────────────┐
│  employee-manager  (社員情報)    vehicle-manager (車両管理)   │
│        ▲ 関数API                        ▲ 関数API              │
│        │ FA_Employee_Bridge             │ FA_Vehicle_Bridge   │
│  ┌─────┴────────────────────────────────┴──────────────┐      │
│  │ ferry-allowance-manager (本プラグイン)               │      │
│  │  管理画面(PHPビュー + admin.js/jQuery)               │      │
│  │     │ admin-ajax.php（nonce + 権限チェック）          │      │
│  │  FA_Record / FA_Route / FA_Company /                 │      │
│  │  FA_Boarding_Name / FA_Summary                       │      │
│  │     │ $wpdb                                          │      │
│  │  {prefix}ferry_records / ferry_routes /              │      │
│  │  ferry_companies / ferry_vehicles                    │      │
│  └──────────────────────────────────────────────────────┘      │
└───────────────────────────────────────────────────────────────┘
```

### 設計方針（ソースコメントから読み取れるもの）

| 方針 | 内容 |
|---|---|
| ブリッジ経由のみで他プラグインを参照 | `emp_*`・`vm_*` 系テーブルを直接クエリせず、公開関数を `FA_Employee_Bridge` / `FA_Vehicle_Bridge` で包んで呼ぶ |
| スナップショット保存 | 実績には登録時点の航路番号・航路名・会社名・手当額・社員コード・氏名・車番・運輸支局を保存し、マスタ変更が過去の給与計算に影響しないようにする |
| 氏名はライブ優先 | 表示時は社員情報から現在の氏名を引き、取れない場合のみ保存済みの氏名を使う |
| 画面はPHP＋Ajax | 画面の骨組みはPHPビュー、一覧取得・保存は `admin-ajax.php` への jQuery 呼び出し |
| 一括保存は全か無か | 入力エラーが1行でもあれば何も登録しない（重複のみ警告で登録続行） |
| 物理削除 | 航路・会社・乗車名・実績の削除は物理削除（元に戻せない）。過去実績はスナップショットのため影響を受けない |

## 5. 技術スタック

| 項目 | 内容 |
|---|---|
| 言語 | PHP（WordPress プラグイン、クラスは `FA_` 接頭辞） |
| DB | MySQL（`$wpdb`、`dbDelta` でテーブル作成） |
| フロント | jQuery（`admin.js` 1ファイル、画面ごとの `init*` 関数を `faData.page` で切替）、`admin.css` |
| ビルド | なし（ファイルをそのままデプロイ） |
| データ受け渡し | `wp_localize_script` で `faData`（ajaxurl、nonce、航路・車番・社員・乗車名マスタ等）を JS へ渡す |
| セキュリティ | 全AJAXで nonce 検証＋権限チェック、SQLは `$wpdb->prepare`、HTMLは `esc_*`／JS側 `esc()` |
| 配布 | GitHub Actions による FTP デプロイ（本番・ステージング・個人テスト） |

## 7. 起動・初期化の流れ

1. `ferry-allowance-manager.php` が定数（`FA_VERSION` など）を定義し、`includes/*` と `admin/class-admin-menu.php` を読み込む。
2. **有効化時**（`fa_activate`）: `emp_get_active_employees` と `vm_get_vehicle_numbers` の存在を確認。無ければプラグインを自動で無効化してエラー表示（「先に employee-manager / vehicle-manager を有効化してください」）。問題なければ `FA_DB_Install::activate()`。
3. **毎回の読み込み時**（`plugins_loaded` → `fa_init`）:
   - 依存関数が無ければ管理画面に赤い通知（「両プラグインが必要です」）を出して機能停止。
   - オプション `fa_db_version` が `FA_VERSION` と違えば `activate()` を再実行（テーブル更新・マイグレーション）。
   - 管理画面なら `FA_Admin_Menu` を生成。
4. `FA_Admin_Menu` が、メニュー・旧URL転送・アセット読み込み・AJAXフックを登録。

【ソース】`ferry-allowance-manager.php`
