# 03 画面仕様（エンジニア／設計者向け）

画面は PHP ビュー（`admin/views/*.php`）で骨組みを描画し、挙動は `admin/assets/admin.js` の `init*` 関数が担当します。どの `init*` を動かすかは `faData.page`（と `faData.tab`）で決まります。

| ページスラッグ(`page`) | タブ(`tab`) | ビュー | JS 初期化関数 | 表示に必要な権限 |
|---|---|---|---|---|
| `ferry-allowance` | – | `entry.php` | `initEntry` | `access_custom_plugins` |
| `ferry-allowance-summary` | – | `summary.php` | `initSummary` | `access_custom_plugins` |
| `ferry-allowance-records` | – | `records.php` | `initRecords` | `access_custom_plugins` |
| `ferry-allowance-master` | `routes`（既定） | `routes.php` | `initRoutes` | `access_custom_plugins` |
| 同上 | `companies` | `companies.php` | `initCompanies` | `access_custom_plugins` |
| 同上 | `boarding-names` | `boarding-names.php` | `initBoardingNames` | `manage_options` |

ビューファイルが存在しない場合は「この画面は準備中です。」を表示（`render_view` のガード）。権限がない場合は `wp_die('権限がありません。', 403)`。

## 1. 共通仕様

### 1-1. JS へ渡すデータ `faData`（`wp_localize_script`）

| キー | 内容 |
|---|---|
| `ajaxurl` | `admin-ajax.php` の URL |
| `page` / `tab` | 現在のページスラッグ／マスタ管理のタブ |
| `nonce.{company,route,record,summary,boarding}` | 各機能の nonce |
| `routes` | 有効な航路の配列 `[{id, route_no, route_name, allowance, company_id, company_name}]` |
| `vehicleNumbers` | vehicle-manager の登録車番一覧（`vm_get_vehicle_numbers()`） |
| `vehicleEmployees` | 乗車名マスタ `{車番: {employee_code, employee_name}}`（有効・実在車番・在籍社員のみ） |
| `employees` | 在籍社員 `[{code, name, crew_code}]`（手動選択モーダル用） |
| `recordFilters` | 実績一覧の絞り込み候補の初期値（当月に実績のある乗車名・車番） |
| `links.vehicle` / `links.employee` | 車両登録（`admin.php?page=vm-vehicle-form`）／社員登録（`admin.php?page=employee-manager-new`）画面のURL |

アセット（`admin.css`/`admin.js`）は、`page` が本プラグインの4ページのいずれかの場合のみ読み込まれます（jQuery依存、バージョンは `FA_VERSION`）。

### 1-2. 共通ユーティリティ（admin.js）

| 関数 | 役割 |
|---|---|
| `faPost(action, nonceKey, data)` | `$.post(ajaxurl, {action, nonce, ...data})` |
| `faFormatNumber(n)` | `toLocaleString('ja-JP')` による3桁区切り（数値でなければ `'0'`） |
| `esc(s)` | HTMLエスケープ |
| `showMsg($box, text, isError)` | メッセージ表示。成功時は3秒でフェードアウト、エラーは残る |
| `parseRouteNo(val)` | 入力文字列から**最初の連続数字**を航路番号として抽出（`"1 神戸 ⇔ 新門司"`→`1`） |
| `toHalfWidth` / `normalizeDate` | 全角数字・`／．－ー―` を半角化、`/` `.` を `-` にして `YYYY-MM-DD` に正規化。実在しない日付は `null` |
| `regLinkHtml(kind)` | 未登録車番・社員の登録画面へのリンク（新規タブ） |
| `manualNameModal` | 乗車名の手動選択モーダル（入力画面・実績編集で共用） |
| `window.FerryAllowance` | `{data, post, formatNumber}` を公開（外部から参照可能） |

### 1-3. 共通UI規約

- 必須項目は `*`（`.fa-req`）。
- マスタ一覧の「無効」行は `is-inactive` クラス（見た目で区別）。
- 入力エラーの赤枠: `is-invalid`。手動選択された乗車名: `is-manual`。重複警告: `.fa-warn`。
- 削除は `window.confirm` による確認ダイアログ。
- 保存ボタンは通信中 `disabled`（二重送信防止）。

## 2. フェリー手当入力（`entry.php` / `initEntry`）

### 2-1. レイアウト

見出し「フェリー手当入力」、説明文、メッセージ欄（`#fa-entry-msg`）、入力表（`#fa-entry-table`）、ボタン「＋ 行を追加」「登録」。

| 列 | 入力要素 | 必須 | 編集 | 備考 |
|---|---|---|---|---|
| 乗車月日 | `input[type=date]`（`.fa-e-date`） | ○ | 可 | コピペの `YYYY/MM/DD` 等も `normalizeDate` で正規化 |
| 航路名検索 | `input[type=text]` + `datalist`（`.fa-e-routeinput`） | ○ | 可 | 候補は `"{番号} {航路名}"`。番号でも航路名でも絞り込める |
| フェリー会社 | readonly | – | 不可 | 航路から自動 |
| 航路 | readonly | – | 不可 | 航路名を自動表示 |
| 車番 | `input[type=text]` + `datalist`（`.fa-e-vehicle`） | ○ | 可 | 候補は vehicle-manager の登録車番 |
| 乗車名 | readonly + 「手動選択」ボタン | ○ | 手動選択のみ | 車番から自動／例外は手動選択 |
| フェリー手当 | readonly（`.fa-e-allow`） | – | 不可 | 航路から自動。3桁区切り表示 |
| 操作 | 「削除」 | – | – | 行削除（0行になれば1行追加） |

フッター「合計」: 全行の手当（`.fa-e-allow`）の合計を即時再計算（`#fa-entry-total`）。

### 2-2. 挙動

| イベント | 動作 |
|---|---|
| 初期表示 | 空行を3行生成。航路・車番の `datalist` を `faData` から流し込む |
| 航路名検索 変更 | `parseRouteNo` で番号抽出→`routeByNo` に存在すれば会社・航路名・手当を反映。存在しなければ3欄を空にし、入力があれば `is-invalid`。合計再計算、末尾空行を自動確保 |
| 車番 変更 | 空→エラーなし。`vehicleSet` に存在→OK。存在しない→`is-invalid` ＋「＋車両管理で登録」リンク表示。手動選択していなければ乗車名を乗車名マスタから自動設定（`setAutomaticEmployee`） |
| 手動選択クリック | モーダルを開く。反映で社員コード・氏名をセットし、ボタンを「選択中」に、`manual-employee=true`。「自動入力に戻す」は手動中のみ表示 |
| 日付 `change/blur` | 正規化して表示。不正なら `is-invalid` |
| 行追加 | 空行を1行追加 |
| 末尾空行の自動確保 | 最終行に日付/航路/車番/乗車名のいずれかが入ったら1行追加 |

### 2-3. 登録ボタンの処理

1. 全行を走査。**4項目（日付・航路・車番・乗車名）がすべて空の行はスキップ**。
2. クライアント検証（行番号は表上の位置 `idx+1`）:
   - 日付なし→「○行目：乗車月日を入力してください。」／形式不正→「○行目：乗車月日は YYYY/MM/DD 形式で入力してください。」
   - 航路が空・不明→「○行目：航路が正しくありません。」
   - 車番なし→「○行目：車番を入力してください。」／未登録→「○行目：車番「xxx」は車両管理ツールに登録されていません。」
   - 乗車名なし→「○行目：乗車名を入力してください。」／社員コード未確定→「○行目：車番に乗車名が紐づいていません。「手動選択」を使用してください。」
3. 有効行が0件→「入力された行がありません。」。エラーがあれば「入力内容にエラーがあります。」＋一覧を表示して送信しない。
4. 送信: `fa_record_save`、`rows_json` = `[{use_date, route_no, vehicle_code, employee_code}]` のJSON。
5. 成功: 「○件を登録しました。」（警告があれば「【重複警告】」を併記）、表を空にして3行再生成、合計を0に、画面上部へスクロール。失敗: サーバーのメッセージと `errors[]` を表示。

> 備考（`note`）は DB・API には存在しますが、入力画面には項目がなく送信もされません（→ `08`）。

## 3. 月次サマリ（`summary.php` / `initSummary`）

| 要素 | 内容 |
|---|---|
| 対象年月 | 年: 当年+1〜当年-3、月: 1〜12。初期値は現在（`current_time` ベース） |
| 表示ボタン | `fa_summary_get`（year, month）を呼び、表を描画 |
| 表の列 | 氏名／フェリー手当（月）／件数。フッターに合計金額・合計件数 |
| 空の場合 | 「この月の実績はありません。」、合計は 0 |
| CSV出力ボタン | 同じ `fa_summary_get` を再度呼び、クライアント側で CSV を生成してダウンロード（ボタンは通信中 disabled） |

CSV仕様: → `04_業務ルール・計算仕様.md` の「CSV出力」。エラー時メッセージ: 「CSV出力用のデータを取得できませんでした。」「通信エラーによりCSV出力できませんでした。再度お試しください。」

初期表示は「『表示』を押してください。」で、自動では読み込まない。

## 4. 実績一覧・編集（`records.php` / `initRecords`）

### 4-1. 構成

1. **編集フォーム**（初期非表示 `#fa-records-editcard`）: 乗車月日（date）／航路名検索／フェリー会社(RO)／航路(RO)／車番／乗車名(RO)＋手動選択／フェリー手当(RO)。ボタン「更新」「キャンセル」
2. **対象年月**（年: 当年+1〜-3、月）＋「表示」
3. **絞り込み**: 乗車月日 開始〜終了（date）／乗車名（select）／車番（select）／「条件クリア」。注記「※乗車月日を指定した場合は、対象年月より優先されます。」
4. **一覧表**: 列＝乗車月日／航路番号／航路／フェリー会社／運輸支局／車番／乗車名／手当／操作（編集・削除）。フッター合計。

### 4-2. 一覧取得 `load()`

- 送信: `fa_record_get_list`（year, month, date_from, date_to, employee_code, vehicle_code）
- トリガー: 「表示」、年・月の変更、乗車名・車番の変更、日付範囲の変更（開始>終了ならエラー表示して中止）、条件クリア
- 応答: `items`（実績）と `filters`（候補）。`updateFilterOptions` で乗車名・車番の候補を**表示期間に実績があるものだけ**に更新（選択中の値は維持）。選択値が候補から消えていれば「すべて」に戻して**再取得**
- 乗車名候補は氏名の日本語順、車番候補は**自然順**（`localeCompare` の `numeric: true`）
- 初期の候補は `faData.recordFilters`（当月の実績が基準）

### 4-3. 並べ替え（クライアント側）

- 列見出し（`data-sort`）クリックで昇順⇔降順。別の列は昇順から。初期は `use_date` 昇順。
- 数値比較: `route_no`, `allowance`。それ以外は日本語ロケール比較（`vehicle_code` のみ自然順）。同値は `id` 昇順。
- 見出しに `aria-sort` と ▲▼ を付与。

### 4-4. 編集・更新

- 「編集」で行の `data-*`（id, date, routeno, vehicle, empcode, empname）から編集フォームを復元。航路欄は「番号 航路名」を復元（航路が有効一覧に無ければ番号のみ）。乗車名は**保存済みの社員コード・氏名**をそのまま採用（自動／手動の区別は復元せず `editIsManual=false`）。
- 車番を変更すると、手動選択中でなければ乗車名マスタから乗車名を再設定。
- 更新前検証: 日付必須／航路が有効一覧にある／車番が登録車番／乗車名あり／社員コードあり。メッセージ: 「乗車月日を入力してください。」「航路が正しくありません。」「車番が正しくありません。」「乗車名を入力してください。」「車番に乗車名が紐づいていません。「手動選択」を使用してください。」
- 送信: `fa_record_update`（id, use_date, route_no, vehicle_code, employee_code）。**`note` は送信されない**。
- 成功: 「実績を更新しました。」（警告があれば併記）→編集フォームを閉じて再読み込み。
- 削除: 確認「この実績を削除します。よろしいですか？」→ `fa_record_delete`。編集中の同一IDなら編集フォームも閉じる。

## 5. 航路マスタ（`routes.php` / `initRoutes`）

### 5-1. フォーム項目

| 項目 | 要素 | 制約 |
|---|---|---|
| 航路番号* | number（min 1, step 1） | 1以上、重複不可 |
| 航路名* | text（maxlength 100） | 空不可 |
| フェリー会社 | select（「— 未設定 —」＋**有効な会社**） | 任意。ページ読み込み時にPHPで生成 |
| フェリー手当（円・0円可）* | number（min 0, step 100） | 0以上 |
| 表示順 | number | 空なら航路番号 |
| 有効 | checkbox（既定ON） | – |

### 5-2. 一覧

列＝番号／航路名／フェリー会社／手当／状態／操作（編集・無効化または有効化・削除）。検索欄（番号・航路名の部分一致、300msデバウンス）、「無効も表示」チェック。並び: 表示順→航路番号。

### 5-3. 動作

- 保存時クライアント検証: 「航路番号は1以上で入力してください。」「航路名を入力してください。」「フェリー手当は0以上で入力してください。」
- 編集: 一覧行の「編集」を押すと、`fa_route_get_list`（無効含む）を再取得して該当IDをフォームに入れる。タイトルは「航路を編集（No.○）」、ボタンは「更新」。
- 無効化/有効化: `fa_route_toggle`。削除: 確認「航路「○」を削除します。よろしいですか？（登録済みの利用実績には影響しません）」→ `fa_route_delete`。

## 6. フェリー会社マスタ（`companies.php` / `initCompanies`）

| 項目 | 制約 |
|---|---|
| 会社名* | text（maxlength 100）、重複不可 |
| 表示順 | number（空は0） |

## 7. 乗車名マスタ（`boarding-names.php` / `initBoardingNames`）

説明文: 「車両管理の車番と、通常乗車する社員を紐づけます。入力画面ではこの設定から乗車名が自動表示されます。変更しても登録済みの過去実績には影響しません。」

| 項目 | 内容 |
|---|---|
| 車番* | select（vehicle-manager の登録車番）。**編集中は disabled** |
| 乗車名* | select（在籍社員、表示「氏名（社員コード）」） |
| 有効 | checkbox（既定ON） |

一覧: 車番／乗車名「氏名（コード）」／状態／操作（編集・無効化/有効化・削除）。検索は車番・**社員コード**（氏名では検索不可）。並び: 車番を数値化した昇順→車番。空表示: 「乗車名マスタが登録されていません。」
クライアント検証: 「車番を選択してください。」「乗車名を選択してください。」。削除確認: 「車番「○」の乗車名設定を削除しますか？」

## 8. 手動選択モーダル（共通）

- タイトル「乗車名を手動選択」。説明「イレギュラー時の乗車名を社員情報から選択してください。この選択が乗車名マスタより優先されます。」
- 選択肢: 在籍社員「氏名（社員コード）」。
- ボタン: 「自動入力に戻す」（手動選択中のみ表示）／「キャンセル」／「反映」。
- 閉じ方: 背景クリック、Escキー、キャンセル。Enterで反映。
- 未選択で反映→「社員を選択してください。」
