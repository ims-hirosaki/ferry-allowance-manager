# 05 データベース設計

テーブルは `FA_DB_Install::create_tables()`（`includes/class-db-install.php`）が `dbDelta` で作成・更新します。テーブル名は WordPress の接頭辞（`$wpdb->prefix`、通常 `wp_`）＋下記の名前です。文字セットは `$wpdb->get_charset_collate()`。

## 1. テーブル一覧と関係

| テーブル | 役割 | ヘルパー関数 |
|---|---|---|
| `{prefix}ferry_companies` | フェリー会社マスタ | `FA_DB_Install::table_companies()` |
| `{prefix}ferry_routes` | 航路マスタ | `table_routes()` |
| `{prefix}ferry_vehicles` | **乗車名マスタ**（名前は vehicles だが「車番⇄社員」の対応表） | `table_vehicles()` |
| `{prefix}ferry_records` | フェリー利用実績 | `table_records()` |

```
ferry_companies (1) ──< (0..n) ferry_routes   （company_id は NULL 可・外部キー制約なし）
ferry_routes    (1) ──< (0..n) ferry_records  （route_id・外部キー制約なし。スナップショットのため参照が切れても可）
ferry_vehicles                                （車番⇄社員コード。ferry_records とは結合しない）
```

> 外部キー制約（FOREIGN KEY）は**定義されていません**。「FK:」とコメントされた列は論理的な参照です。マスタを削除しても過去実績が壊れないようスナップショットを持つ設計です。

外部システム（他プラグイン）との論理的な対応:

| 本プラグインの列 | 参照先（他プラグイン） |
|---|---|
| `employee_code` | employee-manager の社員コード |
| `vehicle_code` | vehicle-manager の一連指定番号（serial_number） |
| `transport_bureau` | vehicle-manager の運輸支局 |

## 2. `ferry_companies`（フェリー会社マスタ）

| 列 | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | INT UNSIGNED AUTO_INCREMENT | NO | – | 内部ID（PK） |
| `name` | VARCHAR(100) | NO | – | 会社名（**UNIQUE** `uk_name`） |
| `sort_order` | SMALLINT | NO | 0 | 表示順 |
| `is_active` | TINYINT(1) | NO | 1 | 有効フラグ（0=無効） |
| `created_at` | DATETIME | NO | CURRENT_TIMESTAMP | 作成日時 |
| `updated_at` | DATETIME | NO | CURRENT_TIMESTAMP ON UPDATE | 更新日時 |

インデックス: PK(`id`)、UNIQUE `uk_name`(`name`)、`idx_sort`(`sort_order`)

## 3. `ferry_routes`（航路マスタ）

| 列 | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | INT UNSIGNED AUTO_INCREMENT | NO | – | 内部ID（PK） |
| `route_no` | SMALLINT UNSIGNED | NO | – | 航路番号（入力キー・**UNIQUE** `uk_route_no`） |
| `route_name` | VARCHAR(100) | NO | – | 航路名（例: 神戸 ⇔ 新門司） |
| `company_id` | INT UNSIGNED | YES | NULL | フェリー会社ID（論理FK。未設定可） |
| `allowance` | INT | NO | 0 | フェリー手当（円・0円可） |
| `sort_order` | SMALLINT | NO | 0 | 表示順 |
| `is_active` | TINYINT(1) | NO | 1 | 有効フラグ |
| `created_at` / `updated_at` | DATETIME | NO | 同上 | 作成・更新日時 |

インデックス: PK、UNIQUE `uk_route_no`、`idx_sort`、`idx_company`(`company_id`)

アプリ側の制約: `route_no` は1以上、`allowance` は0以上（`FA_Route::save`）。

## 4. `ferry_vehicles`（乗車名マスタ：車番⇄社員）

| 列 | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | INT UNSIGNED AUTO_INCREMENT | NO | – | PK |
| `vehicle_code` | VARCHAR(20) | NO | – | 車両管理の一連指定番号（**UNIQUE** `uk_vehicle_code`） |
| `employee_code` | VARCHAR(20) | NO | – | 社員情報の社員コード |
| `is_active` | TINYINT(1) | NO | 1 | 有効フラグ |
| `created_at` / `updated_at` | DATETIME | NO | 同上 | 作成・更新日時 |

インデックス: PK、UNIQUE `uk_vehicle_code`、`idx_employee`(`employee_code`)
→ **1車番につき1人**のみ登録可能。

## 5. `ferry_records`（フェリー利用実績）

| 列 | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | INT UNSIGNED AUTO_INCREMENT | NO | – | 内部ID（PK） |
| `employee_code` | VARCHAR(20) | NO | – | 従業員コード（スナップショット） |
| `employee_name` | VARCHAR(100) | YES | NULL | 氏名スナップショット（表示のフォールバック用） |
| `vehicle_code` | VARCHAR(20) | NO | – | 車番（入力値のスナップショット） |
| `transport_bureau` | VARCHAR(50) | YES | NULL | 運輸支局スナップショット（表示のフォールバック用） |
| `use_date` | DATE | NO | – | 乗車月日 |
| `route_id` | INT UNSIGNED | NO | – | 航路ID（論理FK） |
| `route_no` | SMALLINT UNSIGNED | NO | – | 登録時点の航路番号 |
| `route_name` | VARCHAR(100) | NO | – | 登録時点の航路名 |
| `company_id` | INT UNSIGNED | YES | NULL | 登録時点のフェリー会社ID |
| `company_name` | VARCHAR(100) | YES | NULL | 登録時点のフェリー会社名 |
| `allowance` | INT | NO | 0 | 登録時点のフェリー手当（円） |
| `note` | VARCHAR(255) | YES | NULL | 備考（画面からは入力されない） |
| `created_at` / `updated_at` | DATETIME | NO | 同上 | 作成・更新日時 |

インデックス: PK、`idx_emp_date`(`employee_code`,`use_date`)、`idx_use_date`、`idx_route`、`idx_vehicle`

> `ferry_records` には UNIQUE 制約がありません。同一社員・日付・航路の重複登録を DB は止めません（要件上、警告のみで登録を許可するため）。重複検出は `idx_emp_date` を使うアプリ側クエリで行います。

### 主要クエリ（参考）

| 用途 | 条件・並び |
|---|---|
| 実績一覧 | `WHERE (期間) [AND employee_code=?] [AND vehicle_code=?] ORDER BY use_date ASC, id ASC` |
| 絞り込み候補（乗車名） | `SELECT employee_code, MAX(employee_name) FROM … WHERE (期間) GROUP BY employee_code` |
| 絞り込み候補（車番） | `SELECT DISTINCT vehicle_code … WHERE (期間) ORDER BY vehicle_code ASC` |
| 月次サマリ | `SELECT employee_code, MAX(employee_name), SUM(allowance), COUNT(*) … WHERE use_date BETWEEN 月初 AND 月末 GROUP BY employee_code ORDER BY employee_code ASC` |
| 重複判定 | `COUNT(*) WHERE employee_code=? AND use_date=? AND route_id=?`（更新時は `AND id<>?`） |

## 6. 初期データ（シード）

`FA_DB_Install::seed_routes()`: `ferry_routes` が**0件のときだけ** `default_routes()` の24件を投入（`route_no`=No、`sort_order`=No、`is_active`=1、`company_id`=NULL）。内容は `04_業務ルール・計算仕様.md` の表を参照。

**再投入の条件**: `activate()` はプラグイン有効化時と、`fa_db_version` ≠ `FA_VERSION` のときに呼ばれ、いずれも `seed_routes()` を実行します。航路を全件削除した状態でこれらが起きると、初期24件が再投入されます。

## 7. バージョン管理（マイグレーション）

- WordPress オプション `fa_db_version` に最後に適用したバージョン（`FA_VERSION`）を保存。
- `fa_init`（`plugins_loaded`）で値が違えば `FA_DB_Install::activate()` → `create_tables()`（dbDelta で列・インデックスを追加）→ `seed_routes()` → オプション更新。
- 既存データは維持され、新しい列は dbDelta が追加します（例: 運輸支局 `transport_bureau` 列）。

## 8. テーブル削除（アンインストール）

`uninstall.php` → `FA_DB_Install::drop_tables()` が、**`ferry_records`、`ferry_vehicles`、`ferry_routes`** を `DROP TABLE IF EXISTS` し、オプション `fa_db_version` を削除します。

> **`ferry_companies` は削除対象に含まれていません**（`drop_tables()` の対象配列に無い）。プラグインを削除してもフェリー会社マスタのテーブルは DB に残ります。→ `08` の注意点参照。

「無効化」では何も削除されず、管理画面から「削除」したときだけ実行されます。
